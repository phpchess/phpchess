# phpChess 6 — Decisions

The user's decisions behind phpChess 6, copied from the 4.4 analysis (`phpchess44/PHPCHESS_ANALYSIS.md` §5) so they travel with the code. New decisions are added here first. A decision that is later replaced is struck through, with the replacing one named; it is never deleted. § references point into the analysis.

| # | Decision |
|---|---|
| A1 | No local setup yet; install whatever keeps it fully current. Target **PHP 8.4** (8.3 minimum), **MariaDB 10.11 LTS / MySQL 8.0+**; Composer for development, `vendor/` uploaded. Hosting stays plain shared hosting: the code may not *require* cron, SSH, Node or long-running processes; it detects and uses them when present (cron, `.htaccess` rewrite, unbuffered output). |
| A2 | **Mobile site and PayPal dropped.** A server-verified PayPal integration may come later as its own package. |
| A3 | **No live data.** No data migration, no upgrade path from 4.x, no md5→bcrypt rehash step. |
| A4 | Improvements and current libraries encouraged, in most cases required. Each library is still named in the plan. |
| A5 | **Clean break in look and feel**: modern design, easily replaceable skins, an install-specific look without touching code (§11.6). |
| A6 | Installs fail on shared hosting → **restructure the database** as part of the rebuild (§11). |
| A7 | **Voting tournaments kept** (one primary player vs. a group voting on each move), rebuilt with server-side vote resolution. |
| A8 | **Clubs dropped.** |
| A9 | **Activities dropped**, replaced by seamless access to **Lichess** learning content (§12.6). |
| A10 | **Team vs Team kept** as a tournament format. |
| A11 | **phpChess 6.0 — a complete rebuild** (answers Q1 of §6.1): new code base, 4.4 is the behaviour specification, reuse only what survives review (strings, avatar sets if licensed, rules knowledge). |
| A12 | **Correspondence-centred, with timed play down to 5+3** (revised 2026-11-18, replaces "real-time Blitz"): correspondence is the core; the shortest time control is 5+3 (admin may raise the floor to 10+0); no Bullet, no 3+0/3+2, no WebSocket in the core (§14.1). |
| A13 | **Schools as a target**: easy to run on their own servers, features switchable per install (e.g. direct messaging off). |
| A14 | **A local computer opponent that plays consistently weak** (about 600 Elo or lower), not just "Stockfish turned down". |
| A15 | **League designed from scratch** (2026-11-22), not copied from 4.4's League A/B, with a drag-and-drop interface for arranging players. No 4.4 reference install: the behaviour catalogue comes from the code reading in this document, and 4.4 is run only if one specific question needs it. |
| A16 | **Client-side libraries** (2026-11-22): JavaScript used extensively, under these rules:<br>• a permissive licence (MIT, BSD, ISC). The computer-opponent engine is the one named exception: GPL-3.0 is allowed for it because it is compatible with phpChess's AGPL, and no strong permissive engine with MultiPV is known (user, 2026-11-22);<br>• served from the install itself, never a CDN;<br>• no network access beyond the install's own server;<br>• suitable for children aged 5 and over (no ads, tracking, third-party content or unmoderated external links);<br>• works fully offline;<br>• no known vulnerabilities.<br>"No known vulnerabilities" is checked, not assumed: versions pinned, `npm audit` / OSV check at every update, CSP `connect-src 'self'` so the browser itself blocks any outside request. |
| A17 | **Install without expertise** (2026-11-22): anyone who downloads phpChess 6 from GitHub can install it on shared hosting (the likely case) or a VPS by copying the files, opening one web address and following the steps. Consequences:<br>• the release is a ready-made zip with `vendor/` and the built JavaScript included, so no Composer, npm or command line is needed on the host;<br>• it works when the host can't point the domain at `public/`: it installs into the web root or a subfolder, a root `.htaccess` routes everything to `public/`, and every non-public folder also carries its own deny rule;<br>• the installer proves those folders are unreachable from the browser and stops if they aren't, with a plain-language fix;<br>• Apache and LiteSpeed (most shared hosts) work out of the box; nginx (VPS) gets a ready config snippet shown by the installer;<br>• the installer only needs the database details and the admin account, writes the config itself, and locks itself afterwards. |
| A18 | **Mobile first** (2026-11-22): every page is designed for a phone first. The site installs from the browser to the home screen (PWA) and receives notifications there by Web Push: on iPhone from iOS 16.4, after "Add to Home Screen"; on Android in Chrome and the other major browsers. Native apps for iOS and Android are built only if Web Push proves not good enough in C2-2. **Cost noted**: Web Push sends through the browser makers' push services (Apple, Google, Mozilla). That is the one outgoing connection, from the server, and the device's own browser connects to it too. It runs only while the "push notifications" switch is on, so an offline school install switches it off and keeps in-app notices and email. |
| A19 | **Improve, don't replicate** (2026-11-22): 4.4 is a starting point, not the specification. Starting a game is one tap. There is no wall between correspondence and live play: one game model with any time control. The site knows who is online: moves appear live while both players are there, a push notice goes out when the opponent has left, and a move email when they are offline. |
| A20 | **Modern capabilities throughout** (2026-11-22): drag-and-drop for moves and for arranging anything (League divisions, admin lists, uploads), live updates instead of reloads, share links and QR codes for invitations, offline viewing of your own games, dark mode. Each follows A16. |
